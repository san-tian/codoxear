# Server and API

## Purpose

The local daemon uses the Rust backend as Codoxear's operational/public HTTP entrypoint and background runtime owner, including queue/harness workers, voice scanning, OpenAI-compatible summary/TTS delivery, Web Push, ffmpeg/HLS audio merging, and the Rust broker path. The legacy Python server, Python package, and Python test suite have been removed.

## Key Files

- `backend-rs/src/routes.rs` — public Rust router, auth middleware, stable `/api/*` handlers, and direct static delivery for `/nova-preview/*` plus `/legacy/*`.
- `scripts/codoxear-local` — daemon topology that starts Rust and enables Rust queue, harness, voice scan, voice delivery, and broker workers.
- `backend-rs/src/voice_worker.rs` — Rust voice delivery worker for OpenAI-compatible summary/TTS, Web Push, ffmpeg/HLS, delivery ledger, subscription metadata, and runtime snapshots.
- `codoxear/static/` — legacy browser assets now served at `/legacy/*` by the Rust front door.
- `frontend/dist/` — built Nova preview assets served at `/nova-preview/`.
- `README.md` — public route split and environment configuration.

## Call Chain

1. `scripts/codoxear-local` starts the Rust server with `CODOXEAR_ENABLE_QUEUE_SWEEP=1`, `CODOXEAR_ENABLE_HARNESS_SWEEP=1`, `CODOXEAR_ENABLE_VOICE_SCAN=1`, `CODOXEAR_ENABLE_VOICE_WORKER=1`, and `CODOXEAR_RUST_BROKER_BIN` pointing at the release Rust broker.
2. The Rust request handler checks auth/session cookie state, serves `/`, `/nova*`, `/nova-preview*`, and the migrated public `/api/*` route families directly.
3. Rust serves `/legacy/*` directly from `codoxear/static/`, including the legacy HTML placeholder substitution for asset version and attachment-size constants.
4. Rust serves the public voice settings, listener heartbeat, notification feed/message, and audio playlist/segment routes from shared voice-push files/runtime snapshots plus the persisted listener-heartbeat store.
5. Rust owns the public session/API discovery plus delayed queue-drain, harness, voice-scan, voice-delivery workers, and default web-owned Codex/Pi broker launches. The voice scanner tails newly appended rollout/Pi JSONL records, writes one atomic `APP_DIR/voice_inbox/*.json` file per assistant delivery message, and the Rust delivery worker consumes those files, updates `voice_delivery_ledger.json`, sends Web Push, calls OpenAI-compatible summary/TTS endpoints, and merges audio into HLS output.

## Current Behavior

- `/` and `/nova/` redirect to `/nova-preview/`, making the replatformed shell the active browser entry.
- `/nova-preview/` serves the built Preact/Vite shell from `frontend/dist`, and the public Rust route `/nova-preview/assets/*` now correctly preserves the `assets/` path segment so hashed JS/CSS bundles are read from `frontend/dist/assets/*` instead of incorrectly probing the dist root.
- `scripts/codoxear-local` enables the Rust queue/harness/voice scan/voice delivery workers plus the Rust broker path, and no longer starts `python -m codoxear.voice_runtime`; the status output reports the Rust pid while retaining cleanup for stale legacy pid files.
- Browser clients use same-origin `/api/*` for sessions, transcript polling, diagnostics, queue, harness, files, new session creation, CWD folder suggestions, Codex config editing, local service restart, voice settings, notifications, attachment injection, and legacy file-save. The active Nova preview shell uses file read/search/blob plus attachment injection, while the legacy static file editor remains the only caller of `POST /api/sessions/:id/file/write`, which now also stays on Rust.
- Authenticated `GET /api/version_status` checks the local Codoxear git repository against the configured update remote/ref (`CODOXEAR_UPDATE_REMOTE` / `CODOXEAR_UPDATE_REF`). Without explicit config, it prefers `origin`'s default branch from `origin/HEAD`, then `upstream`'s default branch, then `main`, and reports whether the local HEAD contains that remote HEAD. The route uses `git ls-remote` rather than fetching, so it can show update availability without mutating local refs.
- Public `GET|POST /api/settings/codex_config`, `POST /api/settings/restart_service`, and `GET|POST /api/notifications/subscription` plus `POST /api/notifications/subscription/toggle` are Rust-owned. Rust preserves the `config.toml` raw-text read/write contract, the detached local-daemon restart helper response shape, and the VAPID/subscription persistence contract used by the Nova settings UI.
- Public `GET|POST /api/settings/voice`, `GET /api/notifications/message`, `GET /api/notifications/feed`, `POST /api/audio/listener`, `GET /api/audio/live.m3u8`, and `GET /api/audio/segments/*` are Rust-owned. Rust reads the shared `voice_settings.json`, `voice_delivery_ledger.json`, `push_subscriptions.json`, `voice_runtime.json`, `voice_listeners.json`, and `audio/` files directly.
- Public `GET|POST /api/schedules`, `POST|DELETE /api/schedules/:schedule_id`, `POST /api/schedules/:schedule_id/run_now`, `POST /api/schedules/:schedule_id/enable|disable`, and `POST /api/schedules/:schedule_id/runs/:run_id/mark_done` are Rust-owned. They persist `schedules.json` and `schedule_runs.json` under the Codoxear app dir, and the local daemon starts the Rust schedule sweep worker with `CODOXEAR_ENABLE_SCHEDULE_SWEEP=1`.
- Rust discovers live sessions from the shared socket sidecar metadata for daemon voice scanning, starts each discovered log at its current end offset, tails new rollout/Pi JSONL records, mutes resumed-session delivery while sidecar metadata still has `resume_session_id`, and writes classified assistant delivery messages into `voice_inbox/`. The Rust delivery worker consumes those inbox files, reads `voice_settings.json`, `push_subscriptions.json`, and `voice_listeners.json`, updates ledger/subscription metadata, persists `voice_runtime.json`, and writes HLS playlist/segment files.
- The tmux-backed new-session launch path now waits up to `10.0s` for spawned broker socket metadata instead of failing after the older `3.0s` window, and if the metadata still never appears the server includes the last captured tmux pane output in the API error so browser users can see the real bootstrap failure.
- Authenticated `GET /api/cwd_suggestions?q=...&limit=...` resolves the typed new-session cwd query against the server filesystem, returns matching child directories for the current segment, and blends in recent cwd entries so the Nova modal can offer clickable path completion instead of only a native datalist.
- Authenticated `GET /api/session_resume_candidates?cwd=...&agent_backend=...` annotates each matching session with any saved alias plus a `last_user_message` preview derived from the newest meaningful user prompt in the session log, falling back to the older head-of-log preview only when the tail scan cannot find one.
- Public `GET /api/me` is Rust-owned. The frontend still uses the returned `server_pid` to detect service restarts.
- Public `POST /api/login` and `/api/logout` are Rust-owned. Rust implements the password check plus signed auth-cookie contract, including `SameSite=Strict`, `HttpOnly`, URL-prefix-aware `Path`, proxy-aware `Secure`, and logout cookie deletion.
- Authenticated users can create, list, edit, and delete temporary shared-session sets through `GET|POST /api/v1/share-links` and `GET|POST|DELETE /api/v1/share-links/:share_id`. Share records persist in `APP_DIR/session_shares.json`, store one or more session ids plus per-session nicknames, a generated password hash/hint, expiry timestamp, and capability flags for interrupt, file browsing, and attachment downloads. Nova's main `Share` UI creates these records for the selected same-workspace session set with interrupt, file browsing, and attachment downloads enabled by default, with nicknames copied from the main session display names, and now lists existing share sets so owners can copy/open or close old shares. Viewers log in through `POST /api/v1/share-links/:share_id/login`; Rust issues a signed `codoxear_share` cookie scoped to `/share/:share_id/`, so shared viewers do not need the main `codoxear_auth` cookie.
- Shared viewers use public `/share/:share_id/info`, `/share/:share_id/sessions/:session_id/messages/tail|history|live`, `/send`, `/interrupt`, `/terminal_response`, `/files`, `/file/read`, `/file/blob`, and `/file/download` routes. Every shared route verifies the share cookie, expiry, session membership, and the relevant capability flag before touching the underlying session or filesystem.
- Shared viewers also use `/share/:share_id/schedules...` routes to list, create, run, enable/disable, delete, and mark done schedules that target sessions already in the share set. Share schedule handlers reject new-session target modes.
- `backend-rs/src/routes.rs` now also mounts the already-migrated route families directly on stable public `/api/*` paths and guards those aliases with a Rust-side auth middleware that validates the same signed `codoxear_auth` cookie. Rust now also serves `/legacy/*` directly from `codoxear/static/`, so no public browser route bodies depend on Python anymore.
- The legacy Python proxy/server layer has been removed; stable public `/api/*` paths are mounted directly in Rust and guarded by Rust auth middleware.
- Rust `GET /api/v1/sessions` reads the shared Codoxear runtime app dir and returns session summaries from socket sidecar metadata plus alias, queue, harness, sidebar, file, and recent-cwd state. For very new live sessions whose sidecar still lacks `log_path`, Rust rebinds that field from the process' open rollout log before computing `updated_ts`, busy/idle, and launch metadata.
- Rust `/api/v1/sessions/:id/messages/tail|history|live` reads the discovered session `log_path` and returns transcript response envelopes with byte-offset cursors for common user/assistant text events.
- Rust `/api/v1/sessions/:id/diagnostics|queue|harness|git/changed_files|git/diff|git/file_versions|file/read|file/write|file/search|file/blob` reads persisted runtime metadata plus the session cwd filesystem, returning the support-response shapes the Nova preview expects for diagnostics, queued items, harness config, git working-tree summaries, file previews, file-save conflicts, per-file diffs, and relative-path search. `file/write` resolves paths against the session cwd, enforces optimistic `version` checks for overwrites, returns `409 conflict` payloads for create collisions or stale on-disk content, writes text atomically, and updates `session_files.json` so sidebar/file-history state stays aligned after a save. `git/changed_files` returns an empty successful response for non-git session directories; inside git repositories it runs `git diff --name-only`, `git diff --name-only --cached`, and matching `--numstat` calls, merging staged and unstaged path sets while summing numstat rows for paths that appear in both states. `git/diff` resolves the requested path against the session cwd, rejects targets outside the repo root, honors `staged=1`, and returns the raw `git diff -U3 -- <path>` output. `git/file_versions` resolves the requested path against the session cwd, rejects targets outside the repo root, returns `current_exists/current_size/current_text` for the current worktree file with strict text-only reads, and pairs that with `base_exists/base_text` from `git show HEAD:<rel>` when a tracked base version exists. `file/search` prefers `git ls-files --cached --others --exclude-standard` inside repositories, falls back to a directory walk elsewhere, and preserves ignored-directory, timeout, candidate cap, and `mode/scanned/truncated` response fields. Diagnostics also reads live broker `state` from the session socket so `broker_busy` and token data stay aligned, while queue items preserve the transient `sending` flag because that in-flight marker is written into `session_queues.json` for Rust to read.
- Rust `/api/v1/sessions/:id/rename|delete|edit|send|interrupt|terminal_response|enqueue|harness|inject_file|inject_image|queue/delete|queue/update|queue/move` uses the per-session Unix broker socket path plus shared alias/sidebar/harness/file/queue persistence files. `rename` collapses whitespace, trims to a readable title, persists the value in `session_aliases.json`, and clears the alias when the cleaned name is empty. `edit` validates and persists alias plus `priority_offset` / `snooze_until` / `dependency_session_id` into `session_aliases.json` and `session_sidebar.json`, including self-dependency and missing-dependency rejection; the global `codoxear-session` skill's marker helper uses this route for star, shelve/gray, unshelve, and complete-state conventions. `delete` sends broker `shutdown`, falls back to PID teardown when needed, then clears alias, sidebar dependency, harness, queue, and session-file state for the deleted session. `send` forwards `{"cmd":"send","text":...}` and requires the broker ack to include `queue_len`, while `interrupt` forwards `{"cmd":"keys","seq":"\\x03"}` so the public route sends Ctrl-C through the broker. `terminal_response` validates a detected prompt kind/value from live broker state and sends the associated raw key sequence, currently for the Codex `/goal` replace confirmation. `enqueue` persists queue items into `session_queues.json`, promotes the head into an immediate broker send only when live broker `state` plus rollout-log idle checks agree the session is ready, and otherwise returns the queued item unchanged. Harness writes persist the normalized `harness.json` contract, including the `request` field name, integer validation for `cooldown_minutes` / `remaining_injections`, default `5` minutes and `10` remaining injections, and the normalized response shape. Attachment injection base64-decodes the upload, stages it under `APP_DIR/uploads/<session-id>/`, builds the `Attachment N: <path>\n` line, and sends it through the broker as bracketed paste via `keys`. Queue delete/update/move mutate persisted items by `id` and reject edits against the row currently marked `sending`.
- In the local daemon, Rust runs the delayed queue-drain sweep behind `CODOXEAR_ENABLE_QUEUE_SWEEP=1`, using `session_queues.json`, live broker `state`, and rollout-log idle checks.
- In the local daemon, Rust runs the harness sweep behind `CODOXEAR_ENABLE_HARNESS_SWEEP=1`, using `harness.json`, live broker `state`, persisted queue guards, and last-assistant-tail cooldown logic.
- In the local daemon, Rust runs the voice scan behind `CODOXEAR_ENABLE_VOICE_SCAN=1` and the voice delivery worker behind `CODOXEAR_ENABLE_VOICE_WORKER=1`, using live session discovery and delivery-message classification rules, then consuming atomic `voice_inbox` files internally for summary/TTS/Web Push/HLS work.
- Rust `POST /api/v1/sessions` validates backend/provider/auth/reasoning/service-tier inputs against the launch-default sources, creates a missing cwd on demand, rejects non-directory targets, accepts optional `workspace_cwd` display/grouping metadata for Nova sidebar grouping, blocks `worktree_branch` when `resume_session_id` is present, validates resume targets against the Codex/Pi session-log cwd match, creates derived git worktrees with the `repo-branch-slug` path rule, and returns the `{ok, broker_pid, tmux_session?, tmux_window?}` envelope the Nova preview follows. Tmux launches derive a stable tmux session from `workspace_cwd` when present and otherwise `cwd`, while the individual Codex/Pi sessions remain separate tmux windows. Codex/Pi launches use `codoxear-broker-rs`.
- Rust create-session launches the Rust broker path, with `CODOXEAR_RUST_BROKER_BIN` selecting the binary and `scripts/codoxear-local` pointing it at `backend-rs/target/release/codoxear-broker-rs`. The Rust broker uses the broker-configured sessions directory when discovering newly opened logs, so Pi logs created after startup can still update socket metadata with the real Pi session id/path, and terminal-owned Rust broker launches forward local TTY stdin into the child PTY in raw mode.
- Codex new-session defaults are read from `CODEX_HOME/config.toml`, then can be overridden for this web service with `CODEX_WEB_DEFAULT_MODEL_PROVIDER`, `CODEX_WEB_DEFAULT_PREFERRED_AUTH_METHOD`, `CODEX_WEB_DEFAULT_MODEL`, `CODEX_WEB_DEFAULT_REASONING_EFFORT`, and `CODEX_WEB_DEFAULT_SERVICE_TIER`.
- Pi new-session defaults are read from `~/.pi/agent/settings.json`, `~/.pi/agent/models.json`, and `~/.pi/agent/auth.json`. The visible Pi provider list now always includes Codoxear-discovered custom providers from `models.json` plus Pi’s built-in OAuth providers (`anthropic`, `openai-codex`, `github-copilot`, `google-gemini-cli`, `google-antigravity`), with any additional OAuth-backed providers from `auth.json` appended afterward. This keeps built-in choices such as `github-copilot` available in the web picker even when they are not defined in `models.json`; actual session launch still relies on the server-side Pi auth/env state under the active `PI_HOME`.
- `CODEX_WEB_DEFAULT_MODEL_PROVIDER` is validated against the providers present in `CODEX_HOME/config.toml`; a stale `.env` override such as a removed provider name raises `ValueError: model_provider must be one of ...` during session-default loading and causes `/api/sessions` plus workspace loading to fail until the override is fixed or removed.
- Authenticated clients can read and update the raw Codex `config.toml` at `CODEX_HOME/config.toml` through `/api/settings/codex_config`; that public path now rewrites to Rust `/api/v1/settings/codex_config`, and writes still validate TOML before replacing the file so comments and ordering are preserved when the user edits raw text.
- Authenticated clients can trigger `/api/settings/restart_service`, which now rewrites to Rust `/api/v1/settings/restart_service`; Rust shells out to the local `scripts/codoxear-local restart` helper after a short delay so the POST can return before the current worker is stopped, and `/api/me` still includes the current server pid so the frontend can detect when a replacement worker is back and reload itself.
- Message transcript polling can bind a missing metadata `log_path` from the live Codex process' open rollout log, uses log-derived idle state for Codex sessions once a log exists, and transient stale socket errors during polling return cached session state instead of surfacing as browser-visible 502s.
- Deployments may place the Rust server behind a local or remote reverse proxy; browser clients use same-origin routes and do not depend on a specific host port.
- The live daemon starts no Python process; daemon log scanning plus live push/TTS/audio delivery run in Rust.

## Known Risks

- The server is a large route-dispatch surface; source tests catch some regressions but not every browser interaction.
- Static frontend builds are gitignored; deploy verification must ensure `frontend/dist/index.html` exists after `npm run build`.
- Runtime `.env` can override Codex launch defaults; mismatches between `.env` provider overrides and `CODEX_HOME/config.toml` break startup-sensitive APIs even when the daemon itself is running.
- Most Rust `/api/v1` support routes are runtime snapshots; diagnostics calls the live broker socket for `state`, but queue/harness/file support still relies on persisted runtime metadata and can diverge from live process state in edge cases.
- Rust has its own auth middleware for stable `/api/*` routes, serves `/legacy/*` directly, and is the operational/public front door plus daemon queue/harness/voice scanner, voice delivery worker, and Codex/Pi broker launcher. The Python server/package has been removed.
- Public voice settings/feed/audio reads plus listener heartbeats, summary/TTS, Web Push, HLS output, and `voice_runtime.json` snapshots now come from Rust-backed shared files; stale or missing runtime/audio files can still surface divergence if external OpenAI-compatible APIs, push endpoints, or ffmpeg/ffprobe fail.
- Rust-owned new-session creation depends on the configured `codoxear-broker-rs` binary. If the Rust backend is launched from an unexpected cwd or without the expected runtime binaries, `POST /api/sessions` can fail even though the public Rust server itself is healthy.
