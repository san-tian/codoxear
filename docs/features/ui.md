# UI

## Purpose

The browser UI lets mobile and desktop users select sessions, read transcripts, send or queue input, inspect files/diagnostics, manage voice/notification settings, and operate tmux/web-owned sessions.

## Key Files

- `codoxear/static/app.js` — legacy static UI controller kept in the package.
- `codoxear/static/app.css` — legacy UI styling.
- `codoxear/static/service-worker.js` — notification service worker.
- `frontend/src/app.tsx` — Nova preview owner shell, session state, routing, modals, and action wiring.
- `frontend/src/share.tsx` — Nova shared-session shell and share-login workspace layout.
- `frontend/src/lib/session-status.ts` — centralized frontend session status helpers for awaiting-reply and terminal-error/abort handling.
- `frontend/src/lib/transcript.tsx` — shared transcript event rendering, attachments, file-path chips, and working/waiting rows.
- `backend-rs/src/routes.rs` — Rust routing for `/`, `/nova*`, `/nova-preview*`, `/legacy/*`, and the public same-origin API surface.
- `README.md` — user-facing route and feature descriptions.

## Call Chain

1. User opens the Codoxear web service; `/` and `/nova/` redirect to `/nova-preview/` when the Nova route is enabled.
2. The active Nova preview app authenticates, loads sessions, opens a selected session, and polls/tails transcript endpoints.
3. UI controls call same-origin `/api/*` for send, enqueue, queue, harness, diagnostics, file read, settings, notification, attachment, and interrupt actions.
4. Service worker handles mobile/desktop notification display when registered.

## Current Behavior

- Nova preview session right-click menus expose direct `Normal`, `Star`, `Pending`, and `Snooze` choices for the unified sidebar marker, so users can set any marker state in one step instead of cycling through the marker button.
- `/nova-preview/` is the active browser entry; `/` and `/nova/` redirect there when the local daemon enables the Nova route.
- `/share/:share_id/` and `/share/:share_id/sessions/:session_id/` serve the Nova shell in shared-session mode. The main Nova top bar exposes a `Share` action for the selected session; it opens a compact modal where the owner can name the share set, select sessions across all loaded workspaces, choose an expiry in hours, and create a URL plus temporary password. Interrupt, file browsing, and attachment downloads are enabled by default from that UI path, and shared-session nicknames use the main Nova session names, but the owner-facing modal keeps those defaults implicit instead of showing a separate policy note. The modal's session picker uses a fixed compact checkbox size, explicit session-name/session-id typography, and workspace/path context so selected rows stay readable when share sets span cwd boundaries. The same modal includes a `Created shares` management list where owners can refresh existing share sets, open/copy their URLs, see remaining lifetime plus password hints, and close/delete old share sets; full temporary passwords are only available immediately after creating a share because persisted records store password hashes. Shared viewers authenticate with the temporary share password instead of the main Codoxear password, can switch among sessions in the share set, read transcript history/live updates, send replies into the original session, interrupt when enabled, and inspect/download shared session files when enabled. The shared-session shell lives in `frontend/src/share.tsx`, uses a dedicated two-column layout and standalone share-session row styling so the session list remains visible instead of inheriting the main sidebar marker rail spacing, and keeps `frontend/src/app.tsx` focused on owner state/action orchestration. Its left session list now includes each shared session's cwd/workspace path plus backend and working/queue/idle status, and the selected share transcript uses the same default collapsed tool/ask-user row behavior plus the reusable working/waiting indicator from `frontend/src/lib/transcript.tsx`. It only opens the file detail rail when there are shared files or an active file preview, and on narrow screens the shared session list becomes a compact horizontal strip above the transcript.
- Legacy static assets remain in `codoxear/static/`, are now served publicly by the Rust front door at `/legacy/*`, and are covered by source tests where they still matter.
- The legacy static file viewer still supports in-browser text editing and saves through same-origin `POST /api/sessions/:id/file/write`, which now stays on Rust; the active Nova preview shell still exposes read/search plus attachment injection for session files, but not in-browser file save.
- The UI includes tmux attach-copy affordances for tmux-backed sessions.
- Copy affordances avoid assuming `navigator.clipboard` exists; Nova preview and legacy UI both keep a selection-based copy path for restricted browser contexts. Nova preview transcript user inputs and assistant replies each expose an inline copy button that copies that single message body without including neighboring tool rows or metadata.
- Nova preview uses a wrench icon for the tool/narration visibility toggle and a terminal icon for the tmux attach-copy control. Collapsing that control now hides tool rows, ask-user rows, and assistant narration rows, while keeping user, non-narration assistant, and extension/progress rows visible.
- Nova preview keeps the top-bar rename action as an icon-only edit button on desktop, but on narrow/mobile layouts the top action strip now uses labeled buttons such as `Rename`, `Tools`, `Files`, and `Harness` so the controls remain tappable and understandable. The rename modal still submits on `Enter` as well as the explicit `Save` button.
- Nova preview defaults to the dark theme, supports a legacy Codoxear-inspired light theme, and persists the user's theme choice from Settings through `localStorage`. The current light theme background uses a softer mist-blue page color behind the white panels instead of the harsher earlier blue-gray wash.
- Nova preview polls the authenticated version-status route after login and then periodically; when the configured upstream ref has commits that the local checkout does not contain, the sidebar title shows a compact `NEW` badge beside `Codoxear Nova` as an unobtrusive update prompt.
- Nova preview Settings loads voice, notification, and `config.toml` data independently; a partial request failure shows an inline retry/error state instead of leaving the modal stuck on loading, and mobile push state sync runs after the modal opens.
- Nova preview Settings keeps `Reload`, `Save config.toml`, and `Restart service` actions next to the raw Codex config editor; restarting calls the authenticated restart API and the page automatically reloads after `/api/me` reports a different server pid, so provider changes take effect without a manual shell restart.
- Nova preview new-session dialog still preloads cwd suggestions and resume candidates in the background, but the cwd autocomplete popup now stays closed on first open instead of expanding by default; it opens only after the user focuses or types in the cwd field.
- Nova preview remembers the last successfully created new-session options in browser `localStorage` under `codoxear.nova.newSessionPreferences`: the preferred backend, per-backend provider/model/reasoning/fast-tier values, and the tmux checkbox are reused the next time the new-session dialog opens or the user switches backend tabs. Stored provider and reasoning values are only applied when they still exist in the server-provided choices; otherwise the current server defaults are used.
- For the Pi backend, the new-session provider picker now shows Codoxear-discovered custom providers from `~/.pi/agent/models.json` together with Pi’s built-in OAuth providers (`anthropic`, `openai-codex`, `github-copilot`, `google-gemini-cli`, `google-antigravity`). The picker no longer requires `github-copilot` or the other built-ins to already appear in `auth.json` before the user can select them, although the eventual session launch still depends on the host’s real Pi auth/env state.
- Nova preview uses explicit `starting` and `working` status chips plus a compact bottom transcript working indicator that reuses the transcript row layout and stays left-aligned with the assistant/tool text column, so new-session startup and first-turn processing do not appear idle while Codex initializes tools or MCP servers. For owned sessions that have not published a `log_path` yet, `starting` takes priority over stale local `busy`, awaiting-reply, sending, and queue labels, and the composer treats that startup window as a busy state. The top-bar `working`/`starting` chip is nudged slightly away from the workspace chip for cleaner header spacing, and the `working` chip uses a green accent instead of the older blue palette. The left sidebar now uses the same effective running state for the currently selected session: if the user message has been sent and the UI is still awaiting the first assistant reply, the session dot and workspace `running` count stay lit even before backend `busy` polling catches up. That awaiting-reply state is centralized in `frontend/src/lib/session-status.ts` and is cleared by assistant replies, error tool results, and aborted/cancelled/error extension events, so forced interrupts or remote failures do not leave the UI showing `working` after the turn has ended. When a session still has queued input but is not actively `working`, Nova now treats that as a short waiting state instead of a plain idle/queue label: the top-bar chip, bottom breathing indicator, and sidebar session dot switch to an amber waiting tone while the text still shows the queued count.
- Nova preview’s top-bar Stop action now behaves as an explicit red labeled button instead of a small neutral icon. After the user sends a stop/interrupt signal, `Stopping` is only a short local feedback state; the stopped session then suppresses stale backend busy flags and the awaiting-assistant heuristic from relighting the top bar or sidebar running dot until the backend reports idle/aborted or the user sends a new message. The backing Rust interrupt route sends `Ctrl-C` through the broker instead of a plain ESC byte, making the button match terminal interruption behavior. Session switching now keeps an in-memory per-session view snapshot for transcript, cursors, older-history state, busy/queue state, and token summary: returning to an already opened session restores the cached view immediately while the background tail/live refresh catches up, while sessions without a snapshot still clear runtime-derived state first so a previous session’s green running indicator cannot be inherited.
- Nova preview’s top-bar context/token chip is now explicitly labeled as an estimate (`Ctx est ...`) rather than an exact context-window meter. The numerator comes from the latest parsed token update, while some backends may supply the denominator from local model metadata; the tooltip also explains that any remaining-percent figure is reserve-adjusted rather than a raw fraction of the full model window.
- Nova preview sidebar session previews show the latest user message, not assistant output, the left navigation supports drag-and-drop ordering for workspace groups plus sessions within the same workspace persisted in `localStorage`, a newly opened workspace is promoted to the top only when no previous session used that workspace, new sessions append to the bottom of their workspace group, and refresh polling now pins the first-seen workspace/session order so mobile Sessions drawer rows do not jump around when `updated_ts` changes. Workspace grouping uses `workspace_cwd` when supplied by session metadata and falls back to the real `cwd`, so agent-created sessions from different folders can still sit under one sidebar workspace without changing file/git operations. Workspace headers are styled as flat uppercase group labels with a left rail, while child sessions remain indented cards connected to that rail so the parent workspace and child-session hierarchy is visually distinct. Settings includes a persisted `Compact session cards` appearance toggle; when enabled, sidebar session rows collapse to a single line that shows only the session title plus the existing draft/running/status marker rail. Drag targets show before/after insertion indicators with subtle motion feedback, sidebar session rows now expose one unified marker button with four states (`normal`, `star`, `pending`, `snooze`) instead of separate star and shelve buttons; the button cycles `normal -> star -> pending -> snooze -> normal` and persists through `/api/sessions/:id/edit` using positive priority, negative priority, or `snooze_until`. Sidebar ordering now uses a stable three-part display partition: starred non-snoozed sessions float first, ordinary/pending sessions stay in the middle, and snoozed/shelved sessions move to the end; workspace groups follow the same rule only when all child sessions are shelved. Shelved sessions keep the normal card treatment; the snooze control is transparent by default and only appears as a very low-opacity affordance on hover, focus, or the selected row, while the session-card marker rail keeps draft, running/waiting status, and the unified marker control in a fixed right-side sequence so passive indicators and action buttons do not collide with title truncation.
- The Nova preview left navigation width is responsive again and now supports drag resize from its right edge in desktop mode; the shell keeps a clamped default width, persists a user-chosen width in `localStorage`, reclamps that width when the viewport or right detail rail changes, and keeps sidebar header/card content from forcing overflow past the left column. The sidebar and resizer still hide in collapsed and mobile layouts.
- Nova preview top-bar menu button now behaves differently by viewport: on desktop it still collapses the left navigation into a single-column shell, while on screens `<= 860px` it opens the sidebar as an overlay drawer with a backdrop. In that mobile layout the toggle is promoted to a labeled `Sessions` / `Close` button, the drawer header also exposes its own close button, the drawer closes on session selection or `Escape`, and the top action strip uses horizontally scrollable labeled buttons instead of a row of cramped icon-only controls.
- Nova preview composer keeps the empty-state hint on the same text inset and line-height as typed content, so the prompt text and the first entered line stay visually aligned instead of jumping between two baselines. On mobile, the composer stays in a compact single-row layout when the active session is idle, with tighter outer padding and a shorter textarea; the busy-session Queue/Interrupt mode selector still wraps into a second row for tap safety. Composer drafts are now tracked per session in browser localStorage rather than as one global input value, so switching sessions restores the correct draft, and sidebar session rows show a small draft marker when unsent text exists for that session.
- Nova preview renders adjacent assistant chunks as one visible assistant block, keeps assistant role labels on the left and user role labels on the right without filled backgrounds, aligns user/assistant/tool message bodies in the same center transcript column, only shows `Assistant` once per user-to-assistant turn, and now de-duplicates obvious repeated/overlapping assistant text when live polling delivers the same tail segment again under a fresh event id. Message bodies still render through the Nova markdown renderer for headings/lists/code/blockquotes/tables/links/images, user/assistant second-precision timestamps stay at the lower-left end of message content instead of under role labels, each user/assistant text row exposes a compact footer copy button for that exact message body, `narration` meta only stays on the footer row for the last remaining narration in a turn, assistant and tool message/title backgrounds remain transparent without quote-like left rails, user messages keep a shallow tinted background without a left accent rail, collapsed and expanded tool rows align with the assistant text column, tool rows keep reduced vertical padding, divider lines only appear between adjacent user and assistant text messages, repeated tool-title prefixes are removed from collapsed summaries, matching tool-call titles carry onto tool-result rows when possible, tool rows omit timestamps, and collapsible tool rows use transparent-background CSS-drawn inline chevrons instead of literal `Expand` / `Collapse` labels.
- When the parser emits both a `tool` event and its matching `tool_result`, Nova preview merges them into one collapsible history row instead of rendering separate call/result rows; the collapsed preview prefers the call text, and the expanded view shows separate `Call` and `Result` sections inside that single row with a slight extra rightward inset for cleaner visual nesting. Collapsed merged-tool previews now also special-case `apply_patch` and `write_stdin` using the existing frontend text only: `apply_patch` summarizes changed files from the result payload, while `write_stdin` strips the exec envelope so the preview shows the first real terminal output line or a concise no-output status instead of `Chunk ID`/timing noise.
- Nova preview derives transcript footer meta from `message_class`, not `notification_text`, so notification/voice text cannot replace labels such as `narration`. Narration rows are treated as auxiliary transcript detail for the wrench/Tools visibility toggle and are hidden together with tools when that toggle is collapsed.
- Nova preview auto-follows new transcript output only when the user is already near the bottom of the transcript scroll area; users reading older history are not pulled back to the latest message.
- Nova preview preserves `Load older messages` state from the transcript `tail` / `history` responses instead of letting later `live` polls clear `history_cursor` and `has_older` when those fields are omitted from the poll payload. When older history exists, the button only appears once the transcript is scrolled back to its oldest/top boundary instead of staying sticky while the user reads newer output, and each click now jumps the scroll position to the newest user message from the newly loaded older page so the reader lands on the next earlier user turn instead of remaining pinned at absolute top.
- Nova preview shows local pending user rows for direct sends, keeps busy-session queued messages out of the transcript until the backend later emits them from the session log, and displays the current queue as a compact preview above the composer when queued messages exist. On mobile, the queue preview is height-bounded with per-message line clamping and its own scroll area, so a long queued message cannot expand the sticky composer far enough to cover the top navigation.
- Nova preview renders unresolved `ask_user` transcript rows expanded by default with option buttons and a freeform answer box; choosing a single option or submitting typed text sends the answer directly to the active session through the existing PTY send path so the terminal prompt can continue. Other tool rows remain collapsed by default.
- Nova preview renders normalized plugin `extension` transcript events such as Ralph loop progress as structured display rows with title, status, progress bar, checklist items, and optional body text. Codex Todo/update_plan still drives the floating progress panel above the composer, but its history row now renders as an ordinary collapsed tool call instead of a special structured transcript block; the floating Todo view omits the progress bar while Ralph loop keeps iteration progress visible. Codex goal-mode `extension_kind: "goal"` rows render as compact Goal cards with objective, status, token budget/used/remaining, elapsed time, and completion budget report, so `/goal` state remains visible even when raw tool rows are hidden. The floating progress panel now lives in the same main workspace column as the transcript instead of inside the composer overlay, so opening the right detail/files rail squeezes the panel width together with the chat column, completed floating checklist items render with strikethrough text, the card/status colors now follow the active light or dark theme instead of staying on one palette, and the card header includes a local collapse/expand control so users can temporarily minimize the floating checklist without losing the current progress source.
- The legacy static UI keeps selected-session tail snapshots in memory only; Nova preview also keeps per-session transcript/runtime view snapshots in memory only for smoother switching. Transcript scrollback is not persisted in localStorage, while Nova preview composer drafts and UI preferences may still use localStorage.
- Desktop notification polling and service-worker push support are available through server-side notification routes.
- File viewing and attachment injection are exposed through server APIs. The Nova files panel can open an exact relative path even when there are no tracked or changed files to list, shows local opening/error feedback in the panel, and clears stale previews on failed opens. The desktop right detail rail has a draggable left-edge resizer with its width persisted in `localStorage`, while narrow/mobile layouts keep the stacked panel. File rows open on click, and the search-form action is labeled `Open path` because it opens the typed exact relative path rather than the already listed row. Transcript text now extracts likely mentioned file paths, renders them as compact path chips under the message, and clicking a chip opens the file in the right rail for quick preview. Background file-list refreshes update the list silently without clearing or reopening the current preview, so session/sidebar polling does not make an open file flicker. Nova transcript rendering now recognizes injected `Attachment N: <path>` lines and displays them as compact attachment cards with filename, attachment index, file-type badge, and truncated path instead of letting the full staged upload path dominate the chat text.
- Nova transcript attachment cards can now receive a per-page download href; shared-session pages use that hook to make injected attachments downloadable through the scoped share file-download route without exposing the main authenticated API.

## Verification

- Automated frontend build safety: `cd frontend && npm run build`
- Automated session-status safety: `.venv/bin/python -m pytest -q tests/test_nova_session_status_source.py`
- Automated mobile queue-preview safety: `.venv/bin/python -m pytest -q tests/test_nova_mobile_queue_preview_source.py`
- Manual: load `/nova-preview/`, select a session, send a message, open queue/details/files, and test tmux attach copy when metadata exists.
- Manual (2026-04-27): with a 320px-wide browser viewport, confirmed the `Sessions` button opens the overlay drawer, the drawer shows both backdrop and in-drawer close affordances, and the narrow-screen top action row exposes labeled buttons (`Rename`, `Tools`, `Close`, `Tmux`, `Files`, `Details`, `Stop`, `Harness`) instead of collapsing into an unreadable icon cluster.
- Manual (2026-04-26): in a live `/nova-preview/` session, verified that session-scoped drafts restore the correct composer text after session switches, draft markers appear and disappear with non-empty vs empty drafts, collapsed `apply_patch` rows preview changed files from real result text, and collapsed `write_stdin` rows preview real terminal output instead of the raw exec envelope.

## Known Risks

- Legacy UI source tests are string/source based and do not replace browser automation.
- Mobile browser permission flows for notifications require manual device testing.
- Static asset route changes can break browser entry routing or legacy asset compatibility if not checked in a browser.
